# Pasta `plugins`: integrações nativas Tauri

## Escopo

Esta pasta reúne plugins locais do Tauri que encapsulam capacidades específicas de plataforma. O núcleo Rust usa APIs pequenas e tipadas; o código Android traduz essas APIs para Storage Access Framework, metadata APIs e Media3. Regras gerais de catálogo e playlists não pertencem aos plugins.

Pastas Android `.tauri/tauri-api` são suporte gerado pelo toolchain. Não edite esses arquivos como fonte nem faça correções permanentes somente dentro de artefatos gerados.

## `media-source`

Responsável por escolher arquivos locais, extrair metadados e localizar o bundle transferido; não persiste catálogo nem decide playlists.

### Rust

- `lib.rs`: registra o plugin e exporta a API pública.
- `commands.rs`: comandos permitidos pela ponte.
- `models.rs`: requests/responses serializáveis e metadados normalizados.
- `error.rs`: falhas tipadas convertidas para a fronteira Tauri.
- `mobile.rs`: conexão Rust com a implementação mobile.
- `desktop.rs`: comportamento explícito para plataforma sem implementação.
- `build.rs`: geração/configuração de permissões do plugin.

### Android

- `MediaSourcePlugin.kt`: inicia `ACTION_OPEN_DOCUMENT`, aceita seleção múltipla, preserva permissão de leitura e devolve resultados ao Tauri. O comando `import_bundle` também lê `Musics/rigify/imports/Rigbyfy-import/manifest.json`, retorna apenas arquivos existentes, copia capas referenciadas para o cache privado e preserva o vínculo entre `trackKeys` e playlists.
- `MediaMetadataMapper.kt`: usa `MediaMetadataRetriever` e `ContentResolver` para título, artista, álbum, duração, capa, MIME, tamanho, faixa, disco, ano e gênero.
- `AndroidManifest.xml`: declara acesso a áudio compartilhado (`READ_MEDIA_AUDIO`, ou leitura legada até API 32); a permissão é solicitada no momento da importação.
- `MediaMetadataMapperTest.kt`: valida o mapeamento Kotlin isolável.

Bibliotecas principais: Tauri Android, AndroidX Activity KTX 1.10.1, Core KTX 1.16.0 e JUnit. O módulo usa compile SDK 36, min SDK 21 e bytecode/JVM 1.8.

## `media-player`

Responsável pela reprodução e integração de mídia do sistema; não consulta SQLite nem decide regras de playlist.

### Rust

Os arquivos seguem os mesmos papéis do plugin anterior. `models.rs` define item de fila, comandos e estado; `commands.rs` expõe operações pequenas; `mobile.rs` faz a ponte; `desktop.rs` sinaliza indisponibilidade sem fingir reprodução.

### Android

- `PlaybackService.kt`: `MediaSessionService` que possui ExoPlayer/MediaSession, fila, ciclo de vida, áudio em segundo plano e notificação multimídia.
- `MediaPlayerPlugin.kt`: API Tauri, conexão com o serviço, despacho de play/pause/seek/next/previous/stop e solicitação de permissão de notificação.
- `PlaybackModels.kt`: DTOs e conversão estável do estado Media3 para a resposta do plugin.
- `AndroidManifest.xml`: serviço, tipo de foreground service e permissões necessárias.
- `PlaybackStateMapperTest.kt`: testes do mapeamento de estado.

Bibliotecas principais: Media3 ExoPlayer e Session 1.7.1, AndroidX, AppCompat, Material, Tauri Android e JUnit. O Gradle atual contém declarações de Core KTX em mais de uma versão; Gradle resolve a versão efetiva, mas isso deve ser consolidado numa manutenção futura.

## Permissões

- Cada plugin possui `permissions/default.toml`, comandos autorizados gerados e schema JSON.
- `plugins/permissions/default.toml` faz parte da configuração compartilhada existente.
- A aplicação habilita os conjuntos `media-source:default` e `media-player:default` em `src-tauri/capabilities/default.json`.
- Novo comando não fica disponível automaticamente: atualize lista, geração/schema e capability com o menor escopo possível.

## Contratos e dependências

Fluxo padrão:

```text
TypeScript service → Tauri command Rust → plugin Rust → plugin Kotlin → Android API
                 ← DTO serializado estável ← conversão/validação ←
```

- Os plugins dependem do runtime Tauri e das APIs Android indicadas.
- `src-tauri` depende dos crates locais via caminho e registra os plugins em `lib.rs`.
- `src/services` depende dos nomes e formatos serializados desses comandos.
- Alteração de campo exige atualização coordenada em Kotlin, Rust, TypeScript, testes e documentação.

## Regras de desenvolvimento

- Mantenha o plugin pequeno e agnóstico ao produto: receba fila/metadados prontos e devolva fatos da plataforma.
- Não acesse o banco, não implemente favoritos e não reordene playlists em Kotlin.
- Preserve equivalência conceitual para uma futura implementação iOS, mesmo que APIs sejam diferentes.
- Trate Activity/Service lifecycle, cancelamento, permissões negadas e chamadas repetidas.
- Não bloqueie a main thread com leitura pesada ou I/O.
- Não exponha paths privados em logs de produção.
- Modele erros recuperáveis; não faça panic/`unwrap` no Rust ou force unwrap no Kotlin.
- Novas operações precisam de DTO tipado, permissão mínima e teste do mapeamento/regra isolável.
- Não edite `src-tauri/gen/android` ou `.tauri/tauri-api` como solução permanente; altere o plugin/configuração fonte e regenere.

## Validação

```bash
cargo fmt --check --manifest-path plugins/media-source/Cargo.toml
cargo fmt --check --manifest-path plugins/media-player/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml --target aarch64-linux-android
bun run tauri android dev
```

Execute também testes Gradle dos módulos e valide em aparelho real: seleção múltipla, permissão persistente, formatos suportados, background, tela bloqueada, notificação, fones, Bluetooth, interrupção por chamada e retomada. Um build que compila não substitui esses testes de ciclo de vida.
